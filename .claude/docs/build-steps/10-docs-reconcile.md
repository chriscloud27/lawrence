### 3. `.claude/rules/chatbot.md` — Drizzle/SQLite section

The **Drizzle / SQLite** block describes a workflow that cannot run (`npm run seed`,
`drizzle-kit generate`, `src/Chatbot/db/`). Replace it with a short note that app-owned tables are
currently accessed through `@supabase/supabase-js`, and that [ADR-0013](../adr/0013-production-stack-configuration.md)
names Drizzle for app-owned tables (`leads`, `messages`) with `supabase-js` retained for Auth,
Storage, and Realtime. Neither is installed yet, so describe it as the decided target, not as
current state.

Do **not** delete the "never write raw SQL outside a query builder" rule — that survives regardless
of which client is used.

### 4. Resolve the two-provider contradiction

`.claude/rules/ai-agents.md` mandates `gpt-4o-mini`. `.claude/rules/chatbot.md` mandates
`claude-haiku-4-5`. Both are in force; the project already runs two providers by accident.

Add a short **Model selection** note at the top of both files stating that per-job model routing is
governed by ADR-0015, that the routing table there is a hypothesis under evaluation rather than a
plan of record, and that no model may be hardcoded outside the provider seam introduced in Step 12.

Keep the existing per-file defaults as the *current* values — this step records the contradiction
as deliberate, it does not resolve it. ADR-0015 resolves it.

### 5. Add the stack-audit read trigger

Confirm `CLAUDE.md` Key Files contains the `.claude/docs/stack-audit.md` pointer with its read
trigger ("before proposing, adding, or replacing any infrastructure, hosting, LLM provider, or
library choice"). Added in revision 2; verify it survived.
